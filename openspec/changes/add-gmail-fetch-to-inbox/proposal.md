# Proposal

## Why

QUILL の最初の一歩として、Gmail の新着を定期的に取ってきて、手元の受信箱（SQLite）に漏れなく・重複なく貯める仕組みが必要。③仕分けと④出力は、この受信箱を入力にして後の変更提案で作る。

スパイク（`docs/spike/1a-gmail.md`）で次の2点がわかった。この提案は、それを前提にしている。

- Gmail の検索で `after:` に UNIX 時刻を渡しても、時刻単位では絞れない
- モデルに本文を書き写させると、文字が欠けたり送信者が書き換えられたりする

## What Changes

### 変更要求（何を変えたいか）

- 一定間隔で Gmail の新着を取ってきて、受信箱に保存したい
- 取りこぼしも、二重の保存もしたくない
- 取得に失敗したときに、壊れたデータを保存したり、取りこぼしを生んだりしたくない
- Claude の呼び出しにかかった時間とトークンを、本文を残さずに記録したい
- 今エージェントが何をしているか（取得中・失敗・待機）を、クイルの表情で知りたい

### 仕様の要点（どう振る舞うべきか。詳細は specs/ を参照）

- 間隔（既定30分）ごとに取得する。前回の取得が終わっていなければ、その回は始めない
- 取得対象は、取得元ごとのカーソルより10分前以降に受信したメッセージ。カーソルがない初回は24時間前から
- カーソルは、取得と保存が両方成功したときだけ進める
- 同じ `(source, external_id)` は1回しか保存しない
- Gmail の対象は「受信トレイのメインタブ」に届いたメッセージ。自分が送ったメッセージは除く
- 保存する本文などの値は、モデルの出力ではなく Gmail のツールが返した値そのものを使う
- ツールの返り値がスキーマに合わないときや、取得の手順が欠けたときは、何も保存せず、エラーとして記録し、カーソルを進めない
- `claude -p` の呼び出しごとに、所要時間・トークン数・件数・結果を記録する。本文・件名・送信者は記録しない
- 取得中は `fetching`、失敗時は `error`、成功時は `idle` を renderer に通知し、クイルの表示を切り替える

### 範囲外（この変更ではやらないこと）

- ③仕分け、④出力（todos テーブル、ToDo 一覧、`todo` / `unsure` / `triaging` の状態）
- Slack からの取得（後の変更提案で、2つ目の取得元として足す）
- 設定画面や設定ファイル（間隔などは、この変更では既定値として持つだけ）
- ログイン時の自動起動、キャラ以外のクリック透過
- 古いメッセージの削除（保持期間）
- Gmail への書き込み（既読化、ラベル変更など）

## Capabilities

### New Capabilities

- `fetch-cycle`: 定期的な取得の流れ。実行間隔、多重実行の防止、カーソルと重ね取り、失敗時の扱い、呼び出しの記録
- `message-inbox`: 取得したメッセージの保存。`(source, external_id)` での重複除外と、保存とカーソル更新の一体性
- `gmail-source`: Gmail を取得元にするときの振る舞い。取得範囲、送信済みの除外、読み取り専用の呼び出し、ツールの返り値からの値の取り出しと検証
- `quill-status`: エージェントの状態を renderer に知らせ、クイルの表示に反映すること（この変更では `idle` / `fetching` / `error`）

### Modified Capabilities

なし（既存の仕様はまだない）

## Impact

- **新しい依存**：`better-sqlite3`（`pnpm-workspace.yaml` に `allowBuilds: { better-sqlite3: false }`）、`zod`
- **新しいコード**：`src/main/` の下に、Claude CLI の起動部分、stream-json の解析、Gmail の取得元、受信箱、取得サイクル、スケジューラ、呼び出しログ、状態の決定
- **変える既存コード**：
  - `src/main/index.ts`：取得の仕組みを組み込み、状態を renderer に送る
  - `src/preload/index.ts`：状態を受け取る口を renderer に公開する
  - `src/renderer/index.ts`：仮の切り替えボタンをやめ、通知された状態を表示する
- **データ**：`app.getPath('userData')` の下に、DB ファイルと呼び出しログを作る
- **前提**：`better-sqlite3` の Mac での動作確認（`docs/spike/1b-sqlite.md` の再現手順）が、まだ終わっていない
- **大きさ**：KICKOFF で決めた範囲どおりだが、1〜2日には収まらない可能性がある（design.md のリスクを参照）
