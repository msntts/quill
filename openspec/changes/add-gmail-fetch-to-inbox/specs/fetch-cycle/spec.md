# Spec Delta

## Purpose

取得元ごとの新着を、決まった間隔で、取りこぼしなく・多重実行せずに取ってきて受信箱に渡し、その結果と費用を記録する流れを定める。

## ADDED Requirements

### Requirement: 定期取得

システムは、アプリの起動時に1回、その後は設定した間隔（既定30分）ごとに、取得元ごとの取得を実行する（SHALL）。

#### Scenario: 起動時に取得する
- **WHEN** アプリが起動する
- **THEN** 待たずに取得を1回実行する

#### Scenario: 間隔ごとに取得する
- **WHEN** 前回の取得を始めてから、設定した間隔が経つ
- **THEN** 次の取得を実行する

### Requirement: 多重実行の防止

システムは、前回の取得が終わっていないうちは、次の取得を始めてはならない（MUST NOT）。その回は、後で実行し直さずに見送る。

#### Scenario: 前回の取得が終わっていない
- **WHEN** 間隔が経った時点で、前回の取得がまだ実行中である
- **THEN** 新しい取得を始めない
- **AND** 見送ったことを記録する

#### Scenario: 前回の取得が終わったあと
- **WHEN** 前回の取得が終わったあとで、次の間隔が経つ
- **THEN** 取得を実行する

### Requirement: 取得の対象期間

システムは、取得元ごとのカーソルから重ね時間（10分）を引いた時刻以降に受信したメッセージだけを、取得の対象にする（SHALL）。カーソルがまだない初回は、取得を始めた時刻の24時間前からを対象にする。

#### Scenario: カーソルより前のメッセージは対象にしない
- **WHEN** カーソルが T のときに取得する
- **AND** 受信時刻が T − 10分 より前のメッセージがある
- **THEN** そのメッセージは受信箱に渡さない

#### Scenario: 重ね時間の中のメッセージは対象にする
- **WHEN** カーソルが T のときに取得する
- **AND** 受信時刻が T − 10分 以降、T より前のメッセージがある
- **THEN** そのメッセージを受信箱に渡す

#### Scenario: 初回は24時間前から
- **WHEN** その取得元のカーソルがない状態で、時刻 S に取得を始める
- **THEN** 受信時刻が S − 24時間 以降のメッセージを対象にする
- **AND** それより前のメッセージは受信箱に渡さない

### Requirement: 区切りごとの保存

取得元は、1回の取得の結果を、古い順の区切り（Gmail では UTC の1日分）ごとに返す。システムは、区切りごとに、その区切りのメッセージの保存と、カーソルの更新を行う（SHALL）。ある区切りが失敗したら、それより後の区切りは扱わない。

#### Scenario: 区切りごとに保存する
- **WHEN** 1回の取得で、3つの区切りがすべて成功する
- **THEN** それぞれの区切りのメッセージを、古い区切りから順に保存する

### Requirement: カーソルの更新

システムは、区切りの取得と保存が両方成功したとき、その取得元のカーソルを進める（SHALL）。最後でない区切りでは、その区切りの終わりの時刻（Gmail では UTC の翌日0時）に進める。最後の区切りでは、その回の取得を始めた時刻に進める。失敗した区切りでは、カーソルを変えてはならない（MUST NOT）。

#### Scenario: 成功したらカーソルを進める
- **WHEN** 時刻 S に始めた取得のすべての区切りが成功し、保存も成功する
- **THEN** その取得元のカーソルは S になる

#### Scenario: 新着が0件でもカーソルを進める
- **WHEN** 時刻 S に始めた取得が成功し、対象のメッセージが0件である
- **THEN** その取得元のカーソルは S になる

#### Scenario: 失敗したらカーソルを進めない
- **WHEN** 最初の区切りで、取得・検証・保存のいずれかが失敗する
- **THEN** その取得元のカーソルは、取得を始める前の値のままである

#### Scenario: 途中の区切りで失敗する
- **WHEN** 3つの区切りのうち、1つ目が成功し、2つ目が失敗する
- **THEN** 1つ目の区切りのメッセージは保存されている
- **AND** その取得元のカーソルは、1つ目の区切りの終わりの時刻になる
- **AND** 2つ目と3つ目の区切りのメッセージは保存しない

### Requirement: 取得の失敗

システムは、区切りの結果が検証に通らないとき、Claude CLI が失敗したとき、または制限時間を超えたときは、その区切りのメッセージを1件も保存せず、エラーとして記録する（SHALL）。それより前に成功した区切りの保存は取り消さない。

#### Scenario: 検証に失敗した
- **WHEN** 区切りの結果のうち1件でも検証に通らない
- **THEN** その区切りのメッセージは1件も保存しない
- **AND** エラーの種類を記録する
- **AND** その区切りの分のカーソルは進めない

#### Scenario: Claude CLI が失敗した
- **WHEN** Claude CLI が0以外の終了コードで終わる、または結果を返さない
- **THEN** その区切りのメッセージは1件も保存しない
- **AND** エラーの種類を記録する
- **AND** その区切りの分のカーソルは進めない

#### Scenario: 制限時間を超えた
- **WHEN** Claude CLI が制限時間（既定5分）を過ぎても終わらない
- **THEN** その Claude CLI のプロセスを止める
- **AND** その区切りのメッセージは1件も保存せず、エラーとして記録する

#### Scenario: 失敗の次の回
- **WHEN** 前の回が失敗したあとで、次の間隔が経つ
- **THEN** 前の回が終わった時点のカーソルから取得する

### Requirement: 呼び出しの記録

システムは、Claude CLI を呼ぶたびに、取得元、区切り（Gmail ではその日の日付）、開始時刻、所要時間、トークン数（入力・出力・キャッシュ作成・キャッシュ読み取り）、ターン数、取得件数、保存件数、結果（成功・失敗とその種類）を、ユーザーデータ領域のログに記録する（SHALL）。

#### Scenario: 成功した呼び出しを記録する
- **WHEN** Claude CLI の呼び出しが成功する
- **THEN** 区切り・所要時間・トークン数・ターン数・取得件数・保存件数を含む記録が1件増える

#### Scenario: 失敗した呼び出しも記録する
- **WHEN** Claude CLI の呼び出しが失敗する
- **THEN** 区切り・所要時間・失敗の種類を含む記録が1件増える

#### Scenario: 区切りごとに記録する
- **WHEN** 1回の取得で、3つの区切りを取得する
- **THEN** 記録が3件増える

### Requirement: ログに本文を残さない

システムは、ログにメッセージの本文・件名・送信者・宛先を書いてはならない（MUST NOT）。ログに書いてよいのは、件数、ID、時刻、所要時間、トークン数、エラーの種類だけとする。

#### Scenario: 記録に本文が含まれない
- **WHEN** 本文・件名・送信者を含むメッセージを取得して記録する
- **THEN** ログのどの記録にも、その本文・件名・送信者の文字列が含まれない

#### Scenario: エラーの記録に本文が含まれない
- **WHEN** 本文を含むツールの返り値が検証に失敗して、エラーを記録する
- **THEN** エラーの記録に、その本文の文字列が含まれない
