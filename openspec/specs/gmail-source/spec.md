# gmail-source Specification

## Purpose

Gmail を取得元にするときに、どのメッセージを、どの値で、どれだけ安全に受信箱へ渡すかを定める。Claude はツールを呼ぶ役だけを担い、値はツールの返り値から取る。

## Requirements

### Requirement: 取得範囲

システムは、Gmail の受信トレイにあるメッセージを、タブ（メイン・ソーシャル・プロモーション・新着・フォーラム）によらず、取得元 `gmail` のメッセージとして受信箱に渡す（SHALL）。受信トレイにないメッセージは渡さない。

#### Scenario: 受信トレイのメッセージ
- **WHEN** 対象期間に、受信トレイに届いたメッセージがある
- **THEN** そのメッセージを受信箱に渡す

#### Scenario: メインタブ以外のタブのメッセージ
- **WHEN** 取得結果に、プロモーションなどメインタブ以外のタブに分類された、受信トレイのメッセージが含まれる
- **THEN** そのメッセージも受信箱に渡す

#### Scenario: 受信トレイにないメッセージ
- **WHEN** 取得結果に、受信トレイにない（アーカイブ済みなど）メッセージが含まれる
- **THEN** そのメッセージは受信箱に渡さない

### Requirement: 自分が送ったメッセージの除外

システムは、自分が送ったメッセージを受信箱に渡してはならない（MUST NOT）。スレッドを読むと自分の返信も含まれるため、送信済みのメッセージを取り除いてから渡す。

#### Scenario: スレッドに自分の返信が含まれる
- **WHEN** 取得したスレッドに、受信したメッセージと、自分が送ったメッセージがある
- **THEN** 受信したメッセージだけを受信箱に渡す

### Requirement: 1日ずつの取得

システムは、対象期間の始まりを含む日から、取得を始めた時刻を含む日まで、UTC の1日ごとに区切って Claude CLI を1回ずつ呼び、古い日から順に取得する（SHALL）。1回の呼び出しで検索するのは、その日1日分だけとする。ある日の取得が失敗したら、それより後の日は取得しない。

Gmail の検索は日付単位でしか絞れず、1回の検索で返るスレッドは最大50件で、続きのページを取る手段もない。1日ずつに分けることで、長く起動していなかったあとでも、上限に当たりにくくする。日付の区切りを UTC にするのは、Gmail の日付指定が UTC の0時で区切られることを観測したため（design.md D11）。

#### Scenario: 複数の日にまたがる
- **WHEN** 対象期間の始まりが UTC の 11/20、取得を始めた時刻が UTC の 11/23 である
- **THEN** 11/20・11/21・11/22・11/23 の4日分を、この順に1回ずつ呼んで取得する
- **AND** それぞれの呼び出しで検索するのは、その日1日分だけである

#### Scenario: 1日に収まる
- **WHEN** 対象期間の始まりと、取得を始めた時刻が、UTC で同じ日である
- **THEN** その日の分を1回だけ呼んで取得する

#### Scenario: 日付は UTC で数える
- **WHEN** 対象期間の始まりが、日本時間の 11/20 08:37（UTC の 11/19 23:37）である
- **THEN** 最初に取得する日は、UTC の 11/19 である

#### Scenario: 途中の日で失敗する
- **WHEN** 3日分を取得する途中で、2日目の取得が失敗する
- **THEN** 1日目の取得結果は、その日の分として受信箱に渡す
- **AND** 3日目は取得しない

### Requirement: 読み取り専用の呼び出し

システムは、Gmail を読むために Claude CLI を呼ぶとき、Gmail の検索とスレッドの読み取りのツールだけを許可し、送信・下書き・ラベル変更・既読化・ゴミ箱・迷惑メール・削除などの書き込み系ツールはすべて禁止する（SHALL）。

#### Scenario: 許可するツールは読み取り系だけ
- **WHEN** Gmail を読むための Claude CLI を起動する
- **THEN** 許可するツールの一覧には、Gmail の検索・スレッドの読み取りのツールだけが入っている

#### Scenario: 書き込み系ツールは禁止する
- **WHEN** Gmail を読むための Claude CLI を起動する
- **THEN** 禁止するツールの一覧に、Gmail の書き込み系ツールがすべて入っている

#### Scenario: 権限確認を飛ばさない
- **WHEN** Gmail を読むための Claude CLI を起動する
- **THEN** 権限確認をすべて飛ばすオプションは付けない

### Requirement: 呼び出しの引数の固定

システムは、Gmail を読むために Claude CLI を起動するとき、Gmail のツールが実行される直前に引数を書き換える仕組み（Claude CLI の PreToolUse hook）を付ける（SHALL）。書き換えは次の2つとする。モデルが依頼文と違う値を指定しても、Gmail には決めた値で問い合わせるため。

- 検索：1ページの件数を50（コネクタの上限）にする
- スレッドの読み取り：読み方を本文つき（`PLAIN_TEXT`）にする

あわせて、書き換えの記録を Claude CLI の出力に含めるように指定する。

#### Scenario: 検索の件数を書き換える
- **WHEN** モデルが、1ページ5件で検索を呼ぶ
- **THEN** Gmail には、1ページ50件で問い合わせる

#### Scenario: 読み方を書き換える
- **WHEN** モデルが、本文を含まない形式でスレッドの読み取りを呼ぶ
- **THEN** Gmail には、本文つきの形式で問い合わせる

#### Scenario: 書き換えの仕組みを付けて起動する
- **WHEN** Gmail を読むための Claude CLI を起動する
- **THEN** 書き換えの仕組みの設定と、その記録を出力に含める指定が付いている

### Requirement: 会話の記録を残さない

システムは、Claude CLI を呼ぶとき、Claude CLI が会話の記録をディスクに保存しないように指定する（SHALL）。ツールの返り値に含まれる本文が、ユーザーデータ領域の外に残らないようにするため。

#### Scenario: 記録を保存しない指定を付ける
- **WHEN** Gmail を読むための Claude CLI を起動する
- **THEN** 会話の記録を保存しないオプションが付いている

### Requirement: 値はツールの返り値から取る

システムは、受信箱に渡すメッセージの値（ID、スレッド ID、送信者、件名、受信時刻、本文）を、Gmail のツールが返した値そのものから取る（SHALL）。モデルが最終的に出力した文章や JSON の値は使わない。

#### Scenario: モデルの出力とツールの返り値が違う
- **WHEN** モデルの最終出力に含まれる本文や送信者が、ツールの返り値と違う
- **THEN** 受信箱に渡す値は、ツールの返り値と同じである

#### Scenario: 受信時刻はツールの返り値から決める
- **WHEN** 対象期間かどうかを判断する
- **THEN** ツールが返したメッセージの受信時刻を使う

### Requirement: 取得手順の検証

システムは、1日分の取得について次のすべてを満たさない場合、その日の取得を失敗として扱う（SHALL）。

- 指定した検索条件で検索が行われている
- Gmail の検索とスレッドの読み取りのすべてに、書き換えの記録がある
- 指定した検索条件での検索が、1ページ50件で行われている
- 指定した検索条件で見つかったスレッドを、すべて本文つきで読み取っている
- 指定した検索条件の結果が、件数の上限に当たっていない

件数と読み方は、モデルが指定した値ではなく、書き換えたあとの値で判断する。

件数の上限に当たったとは、返ってきたスレッドが上限（50件）ちょうどで、かつ、検索結果の推定件数がないか、推定件数が50件より多いことをいう。返ってきたスレッドが50件より少ないときは、推定件数によらず上限に当たっていないとみなす（推定件数は推定なので、実際より多く出ることがある）。

モデルが指定外の検索を追加で行っても、それだけでは失敗にしない。

#### Scenario: 指定した検索が行われていない
- **WHEN** 指定した検索条件での検索が1回も行われていない
- **THEN** その日の取得を失敗として扱う

#### Scenario: 書き換えの記録がない
- **WHEN** Gmail の検索またはスレッドの読み取りのうち、書き換えの記録がないものがある
- **THEN** その日の取得を失敗として扱う

#### Scenario: 50件以外の件数で検索された
- **WHEN** 書き換えたあとの値で、指定した検索条件での検索が1ページ50件以外の件数で行われている
- **THEN** その日の取得を失敗として扱う

#### Scenario: 読み取っていないスレッドがある
- **WHEN** 指定した検索条件で見つかったスレッドのうち、読み取られていないものがある
- **THEN** その日の取得を失敗として扱う

#### Scenario: 本文なしで読み取ったスレッドがある
- **WHEN** 書き換えたあとの値で、指定した検索条件で見つかったスレッドを、本文を含まない形式でしか読み取っていない
- **THEN** その日の取得を失敗として扱う

#### Scenario: 推定件数が返ってきた数より多い
- **WHEN** 指定した検索条件の結果が50件で、推定件数が715件である
- **THEN** その日の取得を失敗として扱う

#### Scenario: 推定件数がなく50件ちょうど返ってきた
- **WHEN** 指定した検索条件の結果が50件で、推定件数がない
- **THEN** その日の取得を失敗として扱う

#### Scenario: 50件ちょうどで推定件数も50件
- **WHEN** 指定した検索条件の結果が50件で、推定件数も50件である
- **AND** 50件のスレッドをすべて本文つきで読み取っている
- **THEN** その日の取得を失敗にはしない

#### Scenario: 50件より少なく推定件数がそれより多い
- **WHEN** 指定した検索条件の結果が12件で、推定件数が14件である
- **AND** 12件のスレッドをすべて本文つきで読み取っている
- **THEN** その日の取得を失敗にはしない

#### Scenario: 指定外の検索が追加で行われた
- **WHEN** 指定した検索に加えて、モデルが別の条件でも検索する
- **AND** 指定した検索条件の手順はすべて満たしている
- **THEN** その日の取得を失敗にはしない

#### Scenario: 検索結果が0件
- **WHEN** 指定した検索条件での検索結果が0件である
- **THEN** その日の取得は、新着0件の成功として扱う

### Requirement: ツールの返り値の検証

システムは、Gmail のツールの返り値が想定した形（ID、スレッド ID、受信時刻、ラベルが必ずある）に合わないとき、その日の取得を失敗として扱う（SHALL）。

#### Scenario: 必須の項目が欠けている
- **WHEN** スレッドの読み取り結果のメッセージに、ID・スレッド ID・受信時刻・ラベルのいずれかがない
- **THEN** その日の取得を失敗として扱う

#### Scenario: 返り値が JSON として読めない
- **WHEN** スレッドの読み取り結果が JSON として読めない
- **THEN** その日の取得を失敗として扱う
