# message-inbox Specification

## Purpose

取得したメッセージを、取得元をまたいで一意に、壊れずに保存する受信箱を定める。後の仕分け（③）は、この受信箱を入力にする。

## Requirements

### Requirement: メッセージの保存

システムは、取得したメッセージを、取得元（`source`）、取得元での ID（`external_id`）、スレッド ID、送信者、件名、受信時刻、本文、保存した時刻とともに、ユーザーデータ領域の受信箱に保存する（SHALL）。

#### Scenario: 新しいメッセージを保存する
- **WHEN** 受信箱にまだない `(source, external_id)` のメッセージを保存する
- **THEN** そのメッセージが受信箱に1件増える
- **AND** 保存した各項目を、渡された値のまま読み出せる

### Requirement: 重複除外

システムは、同じ `(source, external_id)` のメッセージを2回保存してはならない（MUST NOT）。すでにあるメッセージを再び受け取ったときは、エラーにせず、保存済みの内容を変えない。

#### Scenario: 同じメッセージを2回受け取る
- **WHEN** 同じ `(source, external_id)` のメッセージを2回保存しようとする
- **THEN** 受信箱にはそのメッセージが1件だけある
- **AND** 2回目は「新しく保存した件数」に数えない

#### Scenario: 重ね取りで同じメッセージが再び届く
- **WHEN** 重ね時間の中にあった保存済みのメッセージが、次の回の取得結果にも含まれる
- **THEN** 受信箱の件数は増えない
- **AND** その回の取得は成功として扱う

#### Scenario: 取得元が違えば別のメッセージとして扱う
- **WHEN** `external_id` が同じで `source` が違う2件を保存する
- **THEN** 受信箱には2件とも保存される

### Requirement: 保存とカーソル更新の一体性

システムは、1回分のメッセージの保存と、その取得元のカーソルの更新を、まとめて成功させるか、まとめて取り消す（SHALL）。

#### Scenario: 保存の途中で失敗する
- **WHEN** 1回分のメッセージを保存している途中で、保存が失敗する
- **THEN** その回のメッセージは1件も受信箱に残らない
- **AND** カーソルは更新前の値のままである
